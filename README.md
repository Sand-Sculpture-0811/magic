# ASTRA · 星命之书（GLM 问答版）

命盘与树洞本地保存仍可直接打开 index.html；AI 问答使用智谱 BigModel 的 `glm-5.3-flash`，需要 Node.js 22+ 服务端。

## 本机启动

复制 `.env.example` 为 `.env`，仅在本机填写 `GLM_API_KEY`。运行 `npm start`，访问 http://127.0.0.1:8765 。不要把密钥放进前端或提交到 GitHub。当前模型名称按用户指定保留，账户权限和可用性需要真实调用确认。

## GitHub 与公网部署

GitHub 管理代码；GitHub Pages 只托管静态文件，不能运行本项目的 AI 服务。可把仓库连接到支持 Node.js 或 Docker 的托管平台。无需安装依赖，启动命令 `npm start`，或使用 Dockerfile。

在托管平台环境变量中设置：
- `GLM_API_KEY`：智谱密钥，设为 secret。
- `GLM_MODEL`：`glm-5.3-flash`。
- `HOST`：`0.0.0.0`。
- `PUBLIC_ORIGIN`：平台分配的 HTTPS 网站根地址，不带末尾斜线。
- `AI_ACCESS_CODE`：至少 16 位的随机私密访问码，设为 secret，与 API 密钥不同。
- `PORT`：服从托管平台注入的端口，未设置时为 8765。

网页公开访问，使用 AI 时需要访问码。访问码仅输入在页面内存中。当前限流为单进程共享上限，适合小范围邀请体验，不是多租户计费系统；需要大规模开放时应增加用户登录、持久化配额与平台级限流。

## 数据流

聊天发送当前问题及最近两轮对话给智谱；选择“结合我的命盘”才附上太阳、上升、MBTI、四柱、周期与已翻开的牌。不会发送生日、出生钟表时间或城市原文。树洞默认只在本机保存；点击“请 GLM 回应”仅发送这一条心情与文字。服务端不记录聊天正文；供应商数据处理遵循其政策。既有离线回答标为历史回应。

网络或模型错误会明确显示，不使用离线规则冒充外部 AI。保留的规则函数不在当前问答路径中调用。

接口参考：[智谱对话补全文档](https://docs.bigmodel.cn/api-reference/模型-api/对话补全)。`npm test` 使用模拟上游与内存请求，不联网、不消耗额度。

## 上升星座

可先选择省份/地区，再选择该地区城市；也可直接输入城市名，两种方式自动同步。选定城市后自动匹配内置代表坐标，无需填写经纬度。大陆内置 370 个地点：333 个地级行政区、4 个直辖市、雄安新区，以及 32 个省/自治区直辖县级地点；保留原港澳台和海外城市。支持简称、全称、省份＋城市，以及自治州简称；“海南”不自动解释为青海海南州，须输入“海南州”或完整名称。未收录地点不会猜测或联网查找，可以留空跳过上升星座。城市选择后填入常用标准 UTC 偏移，请自行核对出生当年的实际时区及夏令时。

太阳星座由太阳黄经近似计算。上升星座由出生瞬间、地方恒星时、黄赤交角和地理纬度计算。时区在各地可能因历史政策变化，城市中心位置也不等于实际出生位置；出生分钟误差可能改变分界附近的结果。算法不包含完整章动/UT1 修正，显示度数不代表专业星历精度。八字换算到北京时间，午夜换日，不校正真太阳时。

参考：[USNO 恒星时算法](https://aa.usno.navy.mil/faq/GAST)、[Swiss Ephemeris 地理坐标说明](https://www.astro.com/swisseph/swephprg.htm)。此项目不使用 Swiss Ephemeris 库。

计算更完整不意味着运势预测更准确。全部解读仅作娱乐与自我反思。

server.mjs 为当前 GLM 服务端，server.test.mjs 为模拟测试，.env.example 为配置模板。file 页面与 localhost 页面的浏览器记录相互独立。

## 城市数据来源

坐标与地名摘自 [和风天气 QWeather LocationList](https://github.com/qwd/LocationList) 的 `China-City-List v202506200`，于 2026-10-22 导入。数据内嵌于 app.js，网页不联网。使用地点代表坐标，不代表出生医院位置；源数据版本不是实时行政区划承诺。

## 从此仓库部署到 Render

仓库地址：https://github.com/Sand-Sculpture-0811/magic

1. 在 Render 登录后，选择 **New → Blueprint**，连接这个 GitHub 仓库。
2. 根目录的 `render.yaml` 会配置 Node 24 服务和健康检查，并请求填写 `GLM_API_KEY` 与 `AI_ACCESS_CODE`。
3. `GLM_API_KEY` 填智谱密钥；`AI_ACCESS_CODE` 填自己设置的至少 16 位私密访问码。两者都仅保存在托管平台。
4. 部署完成后使用 Render 给出的 HTTPS 地址。程序自动使用 `RENDER_EXTERNAL_URL` 作为允许的公网地址，无需手填默认域名。
5. 网页显示模型已配置后，在页面输入访问码并发送一条问题，确认真实模型响应。

绑定自定义域名后，需要把 `PUBLIC_ORIGIN` 改成实际使用的 HTTPS 根地址。健康检查不调用模型，也不需要 API 密钥。免费实例的可用性、休眠策略与额度以 Render 当前规则为准；部署界面应确认使用 free 计划。

## Kamente 等兼容接口

服务端支持 `GLM_BASE_URL` 环境变量，填写与密钥同属平台的完整 HTTPS Base URL（保留其要求的 `/v1` 等路径），程序添加 `/chat/completions`；密钥继续保存在 `GLM_API_KEY`。Kamente 密钥不能配智谱官方地址。不要仅凭教程网页域名推断接口域名，使用订阅教程显示的实际 Base URL。模型名使用订阅支持的精确 ID，当前保留 `glm-5.3-flash`。

当前默认 Base URL：`https://www.kamente.com/v1`（由网站所有者确认），实际请求地址为 `https://www.kamente.com/v1/chat/completions`。若 Render 已配置旧的 `GLM_BASE_URL`，需要同步修改该变量，环境变量优先于代码默认值。

## 空回复排查

GLM 请求默认发送 `thinking.type=disabled`，可通过 `GLM_THINKING` 设为 `enabled` 或 `omit`（省略参数）。需平台实际支持该参数。输出上限 512；有正文但截断时保留正文并标记，空正文时返回明确错误。日志只写 `AI_EMPTY_RESPONSE` 的结束原因、内容类型、是否含思考与输出 token 数，不记录密钥、用户文字或思考正文。

问答提供独立的只读“本次回答”文本框，历史对话可展开查看。默认希望回答在 100 字以内，服务端最多返回 200 字；模型请求输出预算为 512 tokens，并请求关闭思考。平台是否执行该参数以实际服务为准。

## 今日日报与动态视觉

首页新增独立日报，使用省份→城市选择当前所在地，和出生地分开保存。日期按当前城市时区更新；页面返回前台及跨午夜时会检查是否需要换日。内置日期拼贴插画、今日寄语与宜忌、三张幸运刮刮卡（颜色、数字、补给）、天气穿搭与生活指南、月亮/水星/金星/火星的生活意象、四选一正念卡，以及探索入口。

全站采用参考图的留白、纸感和拼贴版式，六组配色由日期、个人资料与已揭晓牌面确定；不是所有人统一粉色。文字对比度已检查。这里的幸运色与数字是娱乐性审美灵感，不表示客观好运或财务收益。

天气通过服务端 `/api/weather` 查询 Open-Meteo，仅发送城市中心坐标，不发送出生资料，也不使用 GLM 额度。预报包含日最低/最高温、降水概率、最大风速和 UV；穿搭按这些值生成。服务异常、日期不符或字段不完整时不展示虚构天气，其他日报功能仍可使用。保留 Open-Meteo 来源标注，若商业化使用应核对供应商许可与方案。

刮卡支持鼠标、触屏拖动和键盘直接揭晓。四张正念卡每天每城市与个人资料组合只能选一张；记录保存在 `astra.daily.v1`，刷新恢复，最多保留 40 份记录。换牌不会重置当天正念卡。切换浏览器、设备或清除 localStorage 后记录不共享。

上线须同时更新 `index.html`、`style.css`、`app.js`、`server.mjs`、`server.test.mjs`、`daily.test.mjs` 和 `package.json`。原密钥、访问码与 GLM 配置不变。直接打开 file 页面可使用日报和小卡，但天气需要服务端地址。
